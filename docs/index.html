What this proves

Grounded in the source, not just internally consistent

✓
The numbers match Nucleus's own workbook.

Automated tests assert the platform's weighted rollup against the source Excel's own computed cells to six decimal places — the 1.15 → 3.37 you see above is Acacia's real number, not a demo placeholder.

✓
Nothing about NS-CMMF is hardcoded.

Controls, weights, scoring scales and recommendations are rows in the database, loaded from the workbook by a script — not constants in the code.

✓
The register can't be gamed with free text.

Every entry is a real control gap run through five tested promotion rules, in a fixed priority order, with no severity field to fudge — the same rules are running live on this page.

Where it's thin

Open questions before this goes further

Full technical detail is in SHORTFALLS.md in the repo. The three worth a conversation first:

⚠
The workbook's own scoring methodology isn't implemented anywhere in it.

Nucleus's materials describe a five-dimension composite score with hard caps ("no named owner → max L2"). The actual spreadsheet just uses a single L1–L5 dropdown — this prototype matched what the file does, not what it claims to do.

⚠
Only one domain of one framework is loaded.

GV is 28 of NS-CMMF's 188 controls; PR alone is 83. The loader is proven to hold all of it — populating it, and the other nine frameworks, is the next real effort.

⚠
Two judgment calls need Nucleus's compliance team, not engineering.

Which controls are "foundational," and what maturity level each regulation actually requires — neither exists anywhere in the source data today.
